# 能力吸收判据

当前范围调整：场地预约已撤下主导航、页面路由和专用账号入口，原因：学校未开放申请、真实预约旅程没走通（见 research/SERVICE-EXPLORATION.md）；保留研究代码，重新打开条件同该文件；以下预约实现记录不表示已发布可用功能。

OnePKU 的目标是把常用校园事务连起来。吸收的是能力、数据模型和可靠实现；每项能力应选择最适合的交互入口。上游有一个页面或命令，并不直接意味着 OnePKU 要增加同名页面。

## 每项能力先回答五个问题

1. **实际收益**：具体替用户减少哪一步重复操作，或者解决哪一种难以集中查看的问题？写出一个真实场景，不能仅以“上游支持”为理由。
2. **所在流程**：它能接到现有课程、资料、作业、通知、成绩或校园卡流程中吗？优先在已有对象旁完成动作，新增页面要有独立的使用理由。
3. **最佳入口**：连续浏览、社区互动、复杂媒体或支付在原站更好时，保留原站。批量检索、跨来源整理和按问题查线索适合 CLI/MCP。集中对比、状态查看、文件选择和结果核对适合 GUI。
4. **结果可靠性**：读操作能否说明缺失/过期/部分失败；写操作能否明确目标、展示发出的内容、确认学校实际结果、处理超时和避免重复发送？做不到的环节交还原站，并明确实际完成到哪一层。
5. **长期负担**：北大实际接口、账户权限、来源变动和开源许可是否核实？优先复用已有库和共享核心；不要为了接一项能力引入另一整套应用状态与登录系统。

以上是取舍问题，不做虚假的分数排名。判断应记录场景、收益、入口、依赖和验收事实。

## 四种落点

| 落点 | 适合的能力 | 接入方式 |
| --- | --- | --- |
| GUI 内完成 | 课程/作业、课件归档、成绩和消费对比、可靠的简单写操作 | 融入现有页面，共用资源与操作记录 |
| 原站办理 | 树洞互动、充值支付、选退课、复杂预约或学校特有流程 | 在相关位置提供明确入口，完成状态以学校为准 |
| CLI/MCP | 按问题检索树洞、跨课搜索、批量整理、Agent 调用 | 共用核心；MCP 尚未安装接入，不能把规划写成现状 |
| 暂缓 | 真实数据不可用、收益不明确、授权协议不清楚、结果不可验证 | 保留原因与重新评估条件，不用假数据或空壳页面补齐 |

## 第一批写入契约

- 文件先通过系统文件选择器进入本地私有暂存目录。确认页展示课程、作业、文件名与大小；选择文件和预览不向学校上传。
- 只有点击“确认提交到教学网”才新建尝试并发出文件。日常作业详情读取使用查看模式。
- 发出前持久保存操作状态。相同操作 ID 不重复发出；同一作业存在待处理记录时，先核对记录。
- 学校提交记录中的附件必须与暂存文件的 SHA-256 匹配，才显示已确认。HTTP 200、按钮点击或本地日志均不单独作为提交成功的证据。
- 超时、连接中断或进程退出后显示结果待确认。重新核对只读取学校记录；用户也可在原站核对后结束本地记录。不会自动重发。
- 登录变化关闭旧页面上下文并清除前端私有操作查询。未发送暂存文件在取消/过期/重启时清理；记录保留 90 天，未确认记录继续保留。
- 首次交付以本地模拟、纯解析测试和原生界面验收为准，不拿用户真实作业做提交测试。首次实际学校提交由用户在界面明确发起。

## 来源与复用

- [PKU CLI](https://github.com/pkuinfo/pkucli)：复用已有作业 multipart 提交协议；补充目标一致性、禁止上传重定向重放、回执核对和本地操作生命周期。
- [PkuClaw pku3b](https://github.com/TheOne2006/PkuClaw/blob/main/crates/pku3b/README.md)：参考稳定作业/尝试/附件对象和只读探索边界；根据其展示的 Blackboard 页面结构独立实现收据读取，不引入整套运行时。
- OneTHU 的功能目录用于查漏；每项仍需落回北大实际场景和接口。树洞浏览没有进 GUI（agent 判断：原站的社区体验更完整，GUI 重做收益低）。
